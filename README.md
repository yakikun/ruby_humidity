## 1\. 作品概要

空の写真から抽出した画像特徴量をもとに、**Ruby標準ライブラリのみ**で実装した自作ニューラルネットワークが1時間後の湿度を推定し、センサー値と組み合わせて安全な自動灌水判断を行うシステムです。

外部のGemを一切使用せず、Ruby標準の配列演算だけで順伝播・逆伝播・学習・推論から安全契約検証までを完結させています。実機の誤動作を防ぐため、常に安全性を最優先したJSON形式の模擬実行を出力する設計となっています。

```
[空の写真] ──(ResNet18)──> [16特徴量] ──> [純Ruby MLP] ──> [湿度推定値]
                                                               ↓
[土壌・環境センサーJSON] ───────────────> [純Ruby判断契約] ──> [安全なドライランJSON]
```

---

## 2\. 経緯・きっかけ

植物の自動給水を行う際、「単に土壌が乾いたら水をやる」だけでなく、「この後雨が降るか、湿度がどう変化するか」を先読みして無駄な水やりを防ぐスマートなシステムを作りたいと考えました。

既存の機械学習フレームワーク（Python/PyTorchなど）を利用すれば手軽にAIを組むことはできますが、ライブラリ内部がブラックボックス化し、環境依存性も高くなります。そこで、「Web開発やスクリプト言語の印象が強いRubyの標準機能だけで、AIの基本アルゴリズムをゼロから構築できるのではないか」「透明性とポータビリティを極限まで高めたシステムを作りたい」という探求心から開発をスタートしました。

---

## 3\. 機能説明

1. **純Rubyによるニューラルネットワーク学習・推論機能**  
   - 4時点（3時間前〜現在）の空画像特徴量（16次元）を入力とし、1時間後の湿度（0〜100%）を予測。  
   - 学習・検証・診断データの分割、標準化処理、過学習を防ぐEarly Stopping（早期終了）まで自動実行。  
2. **センサー入力検査と判断契約機能**  
   - AIの予測結果を鵜呑みにせず、土壌センサーのデータ鮮度、校正状態、雨天フラグなどを厳格にバリデーション。  
   - 不正な入力や異常値を検知した場合は安全側に倒し、散水を停止。  
3. **ハードウェア連携を見据えた安全なドライラン出力機能**  
   - 将来の装置班（実機マイコン等）との接続を想定し、誤散水を防ぐ期限付きの安全判断JSON（`executable: false` / `command: NO_ACTUATION`）を出力。

## 4\. 技術説明

- **開発言語・環境**: Ruby 3.x（標準ライブラリのみ、追加Gem不要）  
- **モデル構造**:  
  - 入力層：16次元（4時点×4統計量）  
  - 隠れ層：全結合層32ユニット＋ReLU活性化関数  
  - 出力層：全結合層1ユニット＋Sigmoid活性化関数（×100して0〜100%にスケーリング）  
  - 総学習パラメータ数：577個  
- **学習アルゴリズム**:  
  - 損失関数: 平均二乗誤差（MSE Loss）  
  - 最適化手法: 確率的勾配降下法（SGD, 学習率 0.03）  
  - 誤差逆伝播による勾配計算

## 5\. 工夫点・苦労点

### ① 【最重要】PyTorch自動微分との数値照合による「計算精度の数学的証明」

自作したニューラルネットワークの勾配計算や逆伝播にバグがないかを証明するため、PythonのPyTorch（`float64`）による自動微分結果とRuby実装の勾配・損失・パラメータ更新量を全件照合するテストを構築しました。 さらに有限差分法による勾配チェックも行い、**全パラメータにおける勾配差の最大値が \$3.33 \\times 10^{-16}\$（倍精度浮動小数点の限界精度）未満であること**を確認し、自作計算エンジンの数学的正当性を厳密に保証しました。

### ② AI出力を過信しない多重の「安全契約」設計

AIの推定値を直接アクチュエータに接続せず、中間に「判断契約」レイヤーを配置しました。センサーデータのタイムスタンプ鮮度や校正フラグ、現在の雨天状態などを検査し、基準を満たさない限り絶対に給水コマンドを有効化しない防御的プログラミングを徹底しました。

### ③ 堅牢なデータ検証・復元パイプライン

CSV入力処理において、欠落・余分な列名、文字列や非有限値（NaN/Infinity）の混入、範囲外データを厳格に検出して拒否します。また、CSVの列順が変わってもヘッダー名から自動で元の特徴量順序に再配置する堅牢な入力機構を純Rubyで実装しました。

### ④ 開発で苦労した点

行列演算ライブラリを使えないため、二重配列や `Enumerable#map` / `reduce` を用いて多次元テンソルの演算や連鎖律（Chain Rule）を手作業で落とし込む必要がありました。次元の不整合や符号ミスによる勾配消失を防ぐため、1層ずつ数式とコードを照らし合わせながらデバッグを重ねました。

## 6\. 今後の課題・展望

1. **学校での実測データによる検証**  
   - 現在はまだ過去のデータでの開発診断段階です。今後は学校で実際に空の写真と同期した実測湿度を集め、新しい未使用期間での評価を行いたいと考えています。  
2. **灌水判断の有効性評価**  
   - 湿度予測の精度（MAE）だけでなく、灌水判断そのものが植物の生育にどう貢献したかを、別の指標で評価したいです。  
3. **フルRuby化への挑戦**  
   - 現在は画像特徴抽出にPython（ResNet18）を使っていますが、将来的には画像入力から推論までをすべてRubyだけで完結させることも視野に入れています。  
4. **実機連携へのステップアップ**  
   - 現在は安全なドライラン出力までですが、装置班との安全確認を経て、実際にポンプ制御に繋げることも将来的な目標です。

## ■ ソフトウェア要件（Linux環境）

- **OS**: Ubuntu 24.04 LTS 等  
- **Ruby**: 3.x（標準ライブラリのみ）  
- **追加Gem**: 不要（`gem install` なしで全機能が動作）  
- **GPU**: 不要（一般的なPCで動作可能）  
- **ネットワーク**: 不要（オフライン環境で学習・推論・テストが完結）

>   
> ※画像からの特徴量抽出（学習データ作成時）にPython 3.x, PyTorch, ResNet18を使用していますが、本提出物（モデル学習・推論・灌水判断デモ・テスト実行）の実行にはPython環境は一切不要です。

## ■ セットアップ手順（Linux環境）

1. Rubyをインストール

```
sudo apt update
sudo apt install ruby -y
```

2. Gitをインストール

```
sudo apt install git -y
```

3. リポジトリをクローン

```
git clone https://github.com/yakikun/ruby_humidity.git
cd ruby_humidity
```

4. テスト実行（動作確認）

```
ruby run_tests.rb
ruby submission/test_irrigation_contract.rb --seed 42
```

5. モデル学習（既存データから）

>   
> 注意: 初回学習には数分かかる場合があります。出力先ディレクトリは新規指定が必要です。

```
ruby run_training.rb --data data/v6_compact_features.csv --output runs/model_s42 --epochs 80 --patience 10
```

6. 推論（予測）

```
ruby run_prediction.rb runs/model_s42/model.json data/v6_compact_features.csv
```

7. デモ実行

```
ruby submission/demo_run.rb submission/demo_run_01
```

## ■ 画像から予測する場合

空の写真から直接湿度を予測する場合は、画像特徴抽出にPython環境が必要です。

### 1\. Python環境の準備

```sh
python3 -m venv .venv
source .venv/bin/activate  # Linux
# .venv\Scripts\activate   # Windows
```

### 2\. 必要なPythonパッケージのインストール

```sh
pip install torch torchvision Pillow
```

### 3\. 画像から特徴量抽出

```sh
.venv/bin/python3 extract_single_image_feature.py my_images/sky_01.jpg output.csv
```

### 4\. 特徴量から湿度予測（Ruby）

```sh
ruby run_prediction.rb runs/model_s42/model.json output.csv
```
